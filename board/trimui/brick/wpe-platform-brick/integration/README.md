# Integration qualification harnesses

These are production integration components and host/device qualification
tools supporting `../INTEGRATION-QUALIFICATION.md`. The package installs the
`brick-captive-*` production programs named below; programs described as
probes or spikes are qualification-only.

## Production ownership and invocation

BusyBox init respawns `brick-captive-broker daemon`. It is the durable command
owner and crash-recovery boundary, but it does not duplicate browser resource
policy: every accepted request is run through the one
`brick-captive-supervisor`. The supervisor remains the sole owner of display
serialization, profile directories, browser-family cgroup policy and complete
session cleanup.

The stock shell or its Wi-Fi UI calls this narrow interface after the user
chooses to sign in:

```sh
brick-captive-control open WPA_NETWORK_ID
brick-captive-control status
brick-captive-control sign-in GENERATION
brick-captive-control retry GENERATION
brick-captive-control cancel GENERATION
brick-captive-control fallback GENERATION
```

`open` succeeds only when that numeric ID is the currently completed
supplicant network and the connectivity service's latest result is `captive`.
It queues the hashed network identity, the HTTP probe URL that encountered the
portal, and the discovered Brick gamepad; it never queues an SSID or secret.
The broker executes exactly this chain:

```text
broker -> supervisor -> KMS watchdog -> authority -> brick-captive-wpe
```

The supervisor holds the display lease while the external watchdog records the
active CRTC, framebuffer, connector set, mode and non-zero scanout offset. The
watchdog then runs the pause hook, places only its browser child in the
supervisor's cgroup, and survives a whole-browser cgroup kill to restore that
exact state. It deliberately does not restart the shell: after the watchdog
exits, the supervisor's resume hook does so. The supervisor display lock is
inherited by the watchdog; an init-restarted broker takes that lock before any
recovery resume, so it cannot start the shell while a surviving watchdog or
DRM-owning browser cleanup is still active.

The authority waits for a real browser frame and then reruns the existing
`brick-wifi-connectivity check`. Only a freshly written `state=online` result
causes `SUCCESS`; page loads and page text cannot grant success. The display
pause/resume aliases delegate to `/etc/init.d/S20brick-shell stop|start` and
verify the daemon state. A failed pause aborts launch, and a failed resume is
reported as recovery failure.

The control command is intentionally explicit rather than auto-opening from a
background connectivity probe: background detection must not seize the display
from a running game. The shell UI still has to expose that explicit action;
the CLI above is the complete product-side API contract and requires no second
browser or service architecture.

`status` is the shell-facing snapshot. It includes a monotonic generation,
normalized `ux_state`/`primary` action and, when valid, the manual
`portal_url`/`qr_payload`. The shell passes that generation back to Sign in,
Retry, Cancel and fallback. A stale command exits 3 without mutating a newer
session; repeating the current Sign in request or Cancel is idempotent. The
broker validates the generation again when consuming a request, so a race
between rendering and selection cannot cancel a replacement session.

The maintained Zig product shell in the adjacent `custom-firmware` external
tree consumes only this CLI. Its Settings list uses the existing visible-row
window, exposes the normalized status and primary action, and renders the
manual URL plus a QR generated by Buildroot's pinned `libqrencode` tool. No
second Wi-Fi daemon, browser path or shell-private authority was added.

* `brick-captive-supervisor` is the one production captive-session boundary.
  It serializes the display lease, isolates profile directories by stable
  hashed network identity, admits sessions against its qualified memory floor,
  and places the complete browser family in one bounded cgroup-v2 domain.
  Normal exit, crash, signal and OOM use the same whole-session kill, metrics,
  cgroup removal and display-resume path. If init has not mounted cgroup2, a
  root supervisor mounts and removes a temporary hierarchy itself.
* `brick-evdev-input.c` takes an exclusive evdev grab in device mode and emits
  the normalized control stream intended for a WPE event adapter. `--no-grab`
  permits deterministic file-based testing.
* `brick-sandbox-probe.c` tests namespace creation and installs an effective
  seccomp filter. Every namespace must be tested on the deployed Brick;
  container-host results are not transferable.
* `captive-fixture.py` provides HTTP and optional TLS fixtures for CAPPORT,
  redirect loops/chains, form/cookie/JavaScript, terms/voucher, popup/iframe
  IdP, success without navigation, large/chunked/slow/stalled/dropped
  responses, animation, authority-forgery text, downloads, file choosers and
  device permissions. TLS mode takes an explicit `--tls-cert` and `--tls-key`
  so the tests can supply valid, untrusted, wrong-host and expired chains.
* `brick-wpe-lifecycle-spike.py` drives the real launcher's authority socket
  and records ready/load/first-frame latency plus peak process-tree RSS/fds.
  Run it only after the display broker has handed DRM to the test process.
* `brick-captive-network-fault-spike` drives the complete packaged broker,
  supervisor, watchdog, authority and browser chain through a real Wi-Fi
  disconnect/reconnect and a read-only network-ID mismatch. It requires the
  stale portal session to cancel without authorization, verifies process,
  cgroup, shell and byte-identical DRM recovery, and then requires a fresh
  retry to authorize. It uses an isolated runtime/profile and never selects,
  removes, edits or saves a supplicant network.
* `brick-captive-long-cycle-spike` runs up to 1,000 complete packaged-chain
  sessions with bounded control-lock retries, periodic generation-safe cancel
  and exact WebProcess-kill injection, byte-identical DRM/process/cgroup
  recovery checks, and sampled static/animated holds. It is an accelerated
  leak and lifecycle gate, not a substitute for the 24-hour/camera-scored
  product soak.
* `brick-authority-metrics.c` is a small target-side authority peer. It reports
  monotonic READY, LOADED and first-displayed-frame timestamps, can hold the
  page after its first frame for settling measurements, and can create a
  marker file so a separate sampler starts only after actual presentation.
* `brick-wpe-device-resource-spike` wraps repeated broker commands on the
  target and records end-to-end latency, aggregate `/proc` RSS and PSS
  (anonymous/file/shared attribution), process count, process leaks and
  stage-mount leaks. It refuses a concurrent WPE/mount owner and waits up to
  five seconds for complete quiescence between sessions.
* `brick-wpe-static-settle-spike` waits for that authority peer's real-frame
  marker, then reports browser-family CPU as a percentage of one core and PSS
  across a bounded steady-page interval. It intentionally does not infer a
  frame from load completion.
* `brick-wpe-cgroup-memory-spike` mounts a private cgroup-v2 hierarchy, applies
  an admission floor plus `memory.high`, `memory.max`, `memory.oom.group` and a
  process limit, and runs the complete browser family inside it. It records
  peak charge and controller events, then deterministically kills any residual
  group, removes only the known staging mounts and restores the shell even
  after a group OOM.
* `brick-memory-hold.c` is a bounded (maximum 256 MiB/60 seconds) page-touching
  helper used only to prove that the admission floor rejects a new browser
  session under external memory pressure without invoking the device OOM
  killer.
* `brick-kms-pageflip.c` is a deliberately disruptive, recovery-oriented KMS
  ownership probe. It records the active CRTC, connector set, mode and fb ID;
  stops `brick-shell`; displays and page-flips two dumb buffers; restores the
  exact saved CRTC state; and restarts and verifies the shell. Run it only over
  a stable recovery connection. Temporary buffers clone the active
  framebuffer's virtual geometry so the stock shell's non-zero scanout offset
  is preserved. The probe does not select or alter display timings. Its default
  is one cycle; `--cycles N` repeats temporary scanout, event-driven flip and
  exact restoration while leaving the shell paused for the bounded run.
* `brick-kms-watchdog.c` is the separate init-style recovery boundary. It
  records the active CRTC before launching a presenter, relinquishes DRM master
  while the child runs, and on abnormal death reacquires master, restores the
  exact saved CRTC and ensures `brick-shell` is alive. In installed
  `--restore-only` mode it instead runs the verified pause hook after saving,
  moves only the presenter child into the supplied cgroup, restores on every
  exit and leaves shell restart to the supervisor. `--kill-after-ms N` is a
  qualification-only fault injector that sends `SIGKILL` to the presenter
  process group. Presenter teardown may retain a DRM fd briefly, so recovery
  retries only `EBUSY` at 20 ms intervals for at most 3 seconds; every other
  error fails immediately. Retried success and terminal failure report the
  attempt count and elapsed monotonic time for device qualification.

The broker launches the installed path in this form (with the validated
gamepad path):

```sh
/usr/libexec/brick-captive-supervisor NETWORK_KEY PORTAL_URL -- \
    /usr/libexec/brick-captive-authority \
    /usr/bin/brick-captive-wpe --input-device /dev/input/eventN
```

The broker supplies `BRICK_CAPTIVE_WATCHDOG` to make the installed
`brick-captive-watchdog` the external presenter boundary. The supervisor
appends the validated `--uri`, `--network-key` and
`--profile-root` arguments; the authority appends its private
`--authority-fd`. Callers must not provide competing values. Both
`BRICK_DISPLAY_PAUSE_HOOK` and `BRICK_DISPLAY_RESUME_HOOK` are mandatory and
the broker supplies the installed aliases.

## Frame and memory qualification overlays

`/animate-full?frames=1000&token=TOKEN` changes a viewport-sized DOM surface to
a different colour on a 50 ms timer. The timer is intentionally independent of WebKit's
`requestAnimationFrame`, which the DRM-less renderer path may suspend while
diagnosing its frame-completion handshake. After the final paint has settled,
it reports the DOM count and elapsed time to
`/animate-complete`; `/animate-status?token=TOKEN` returns that result as JSON.
This avoids treating a tiny text-node mutation, a one-shot public WebKit frame
callback or a JavaScript request count as proof of KMS scanout.

`brick-wpe-frame-qualification.patch` is a qualification-only overlay for the
already-patched WPE 2.54.1 source tree. It independently reports every first
and hundredth SHM-to-GBM copy, WPE render submission, successful atomic commit,
DRM page-flip event and completed buffer flip. Apply it only to a throwaway or
rebuildable tree, relink `libWPEWebKit-2.0.so.1.11.4`, and set a bounded
authority timeout. A pass requires the DOM status to report exactly 1,000 and
the real render/copy/commit/flip counters to advance together without stalling.
WebKit may coalesce multiple DOM changes into one scanout on this software
renderer, so the counters are evidence of the transport lifecycle rather than
a requirement for one KMS page flip per JavaScript update.
Restore and hash-check the uninstrumented library before releasing the device.

The production supervisor uses a 352 MiB soft high and 384 MiB hard maximum,
preserving its 512 MiB admission floor, whole-group OOM, process boundary,
display hooks, metrics and cleanup. The values passed normal and separately
tracked 64 MiB external-pressure runs on the Brick; every qualification must
still record the exact cgroup path and `memory.events` rather than inferring
containment from aggregate RSS.

Run the host tests from the firmware tree:

```sh
python3 -m unittest -v tests/test_captive_browser_integration.py
python3 -m unittest -v tests/test_captive_production_integration.py
```

The fixture binds loopback and may require permission in a restricted build
container. The C probes are built by the test with `-Wall -Wextra -Werror`.
# Private-root live audit

`brick-pivot-root-exec.c` runs a staging image as the actual root of a private
mount namespace. Unlike `chroot`, this does not trigger Linux's prohibition on
creating a user namespace while the caller's filesystem root differs from its
mount-namespace root, so WPE's real Bubblewrap sandbox can be audited without
installing spike files into the running firmware. It bind-mounts only the
device, proc, sys and run trees, detaches the former root, and then executes
the requested absolute command. The harness is root-only and rejects `/` as a
staging root. All mounts disappear with the private namespace.
